## 4. COLOUR FEATURE (the most important functional change)
Goal: when I upload a COLOUR image, the reconstruction from the two shares must show the image in COLOUR (today it comes out black and white).

Implement these modes. Keep the existing B/W schemes untouched.

### Mode A: "Colour Overlay 2-out-of-2 (P5, Hou-style CMY)": works with physical stacking
1. Load as RGB. Normalise: apply EXIF orientation, composite any alpha onto white, convert palette/CMYK/16-bit to 8-bit RGB. Resize so the long side is at most 320 px by default (user can choose up to 512), because shares are 2x larger.
2. Convert to CMY: c=255-R, m=255-G, y=255-B (ink amount).
3. Halftone each channel independently with Floyd-Steinberg error diffusion (Pillow `Image.convert("1")` on the L-image of ink amount is fine). ink=1 means ink present.
4. For each channel apply the Naor-Shamir (2,2) construction: each pixel becomes a 2x2 block of subpixels; choose one of the 6 patterns having exactly 2 inked subpixels at random (cryptographically secure randomness: Python `secrets`-seeded numpy Generator, or `crypto.getRandomValues` in the browser), independently per pixel and per channel. If the channel pixel is 0 (no ink) share 2 gets the same pattern; if 1 (ink) share 2 gets the complement.
5. Compose each share image: subpixel colour = (255*(1-c), 255*(1-m), 255*(1-y)). So a subpixel is white, cyan, magenta, yellow, red, green, blue or black. Stacking two shares equals per-channel MIN (multiply blend); verify this equals the OR of inks.
6. Reconstruct has two display options (toggle, default = Enhanced):
   - Raw stack: per-channel min of the two shares (what a real transparency overlay shows).
   - Colour recovery (display enhancement): average each 2x2 block per channel into ink coverage (0.5 = no ink, 1.0 = ink), threshold at 0.75 to recover the halftoned CMY bits at secret resolution, map to RGB, then a very light Gaussian smoothing (sigma about 0.8). Label it clearly as "display enhancement using both shares; no extra information". Result must look like the original in colour.
7. Export shares as lossless PNG only (never JPEG).

### Mode B: "Colour XOR n-of-n, exact colour (XOR principle of P6)": digital combine, perfect result
- Work on full 8-bit R, G, B channels. For n shares: shares 1..n-1 are uniformly random bytes (secure randomness), share n = secret XOR share1 XOR ... XOR share(n-1). Reconstruct = XOR of all shares. No pixel expansion. Output must equal the original resized image BYTE FOR BYTE. Keep the existing n limits. State honestly in the About tab that this is an 8-bit-channel extension of the XOR idea in P6 and needs a computer to combine (not a physical overlay).
